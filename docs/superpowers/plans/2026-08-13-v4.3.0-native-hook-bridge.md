# V4.3.0 Native Hook Bridge Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement V4.3.0 as a capability-selected Hermes integration that uses official plugin hooks for lifecycle events and the minimum strictly owned patch surface for gaps that Hermes v0.20 does not expose.

**Architecture:** Execute five dependency-ordered milestone plans. The pure selector establishes the shared decision contract; the runtime bridge establishes official lifecycle ownership and Sidecar idempotence; the mode-aware patcher removes duplicate producers; the installer makes plugin config and source ownership recoverable; release convergence exposes sanitized readiness and proves the candidate. A milestone is independently testable, but V4.3.0 is not complete until every milestone and the final full-suite gate pass.

**Tech Stack:** Python 3.9–3.12, Hermes Agent plugin entry points, aiohttp, Feishu Card JSON 2.0, AST-based reversible patching, YAML config, setuptools, pytest, POSIX shell, PowerShell, Docker Compose.

## Global Constraints

- The approved design is `docs/superpowers/specs/2026-08-13-v4.3.0-native-hook-bridge-design.md`; it is authoritative when a milestone summary is ambiguous.
- Active source is `hermes_feishu_card/`; do not edit `legacy/`.
- Never hand-edit an installed Hermes `gateway/run.py`; only `hermes_feishu_card/install/patcher.py` owns generated source patches.
- Current Hermes v0.20 / `v2026.8.3` is expected to select `hybrid`; current evidence does not justify `native-hooks`.
- Hybrid unique producers are enforced at source: official hooks own started, ordinary terminal, stable tool, approval observer, and subagent lifecycle; patch-owned code must not emit duplicates.
- Only an explicit structured Sidecar result with `ok=true` and `applied=true` grants card ownership or suppresses native terminal text.
- Missing, ambiguous, timed-out, malformed, or drifting evidence fails open for runtime delivery and fails closed for installation mutation.
- Plugin callbacks return `None`, register no tools, grant no tool override, and never auto-approve.
- All registries, queues, previews, event-id fences, and diagnostics are bounded and sanitized.
- Manifest v3 unknown version, phase, mode, group, backup ID, target, config, entry-point, or capability ownership is never guessed.
- Config preimages stay under the explicitly bound `HERMES_HOME` private state, never in the checkout, manifest output, logs, health, or cards.
- Install/restore/repair/update never auto-restart Gateway; restore/uninstall never pip-uninstall the running HFC package.
- Every product change follows RED → minimal GREEN → focused regression → commit.
- Protect the main checkout's untracked `docs/code-review-v4.2.4-2026-08-01.md` and `docs/superpowers/plans/2026-08-01-v4.2.5-audit-fixes.md`; all work occurs in `.worktrees/v4.3.0-native-hook-bridge`.
- Push, PR, merge, tag, GitHub Release, public asset publication, and real Feishu messages require separate authorization.
