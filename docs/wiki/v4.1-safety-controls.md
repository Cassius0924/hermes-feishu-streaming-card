# V4.1 安全控制与排障

这页是 V4.1.0 的运维入口，覆盖按会话原生投递、表格溢出、Hermes runtime 完整性和 sidecar 服务管理。任何输出、日志或 issue 证据都必须遮蔽 chat id、message id、secret、本机路径和 recovery fingerprint。

## 按会话切换投递

单 profile 配置：

```yaml
bindings:
  native_chats: []
```

多 profile 必须把列表写在 `profiles.<profile_id>.bindings.native_chats`；它不继承顶层值。只允许精确匹配，wildcard、regex、prefix 和空值都无效。

```bash
hermes-feishu-card chats use-native CHAT_ID --config CONFIG
hermes-feishu-card chats use-card CHAT_ID --config CONFIG
hermes-feishu-card chats list --config CONFIG
```

多 profile 时三条命令都加 `--profile-id ID`。命令输出只给 masked 摘要，修改从下一条新消息开始生效。若 `POST /delivery/policy` 的 `hfc-policy-v1` proof、配置 reload 或响应失败，hook 必须 fail-open 到 Hermes 原生路径；sidecar 也必须在创建 CardSession 前再次拒绝卡片路径。`/hfc` 管理命令与显式 smoke card 不受 `native_chats` 影响。

Issue #162 的多机器人群聊若依赖 bot-to-bot mention，必须把该群加入 `native_chats`，让 post 创建时就带 `@bot`；被 @ 的目标应用还要开通 `im:message.group_at_msg.include_bot:readonly`。流式卡片在后续 PATCH 中出现 mention，不会补发新的 `im.message.receive_v1`。策略按 turn 固定，不能扫描模型答案后再中途切换。

## 表格与 28,000 byte 预算

```yaml
card:
  table_overflow_mode: compact  # compact | truncate
```

`compact` 保留所有数据：第 6 张及后续 Markdown 表格转成“表格 + 行 + 字段”列表。scanner 忽略 fenced code 中的 `| fake | table |`，也处理 escaped pipe 与 inline code。`truncate` 仅供需要旧行为的用户显式选择。

最终预算按真实序列化 JSON 计算，而不是 Markdown 字符数：最多 5 张 Feishu table、200 个 tagged element、28,000 UTF-8 byte。非终态超限时保留小型等待卡；终态仍超限时先写入无正文、无原始 chat/message id 的 delivery record，再返回 `applied:false, disposition:native`，由 Hermes 原生发送完整答案。已存在卡片的简短 handoff notice 仅在当前进程内异步尝试，不阻塞 native descriptor，也不承诺跨重启修补；崩溃恢复由 Hermes delivery ledger 的 obligation hash、稳定 Feishu UUID 与 ledger `delivered` 后签名 ACK 保证。重复 terminal 不应产生第二份答案。

## integrity 模式与升级迁移

```yaml
integrity:
  mode: safe  # safe | notify | off
```

- 新 setup/example 写 `safe`。
- 旧配置缺少该段时按 `notify` 加载，不做自动 mutation。
- `off` 关闭 runtime control plane，但普通事件 auth 和 `doctor` 仍有效。

启用旧安装的 `safe` 前：

```bash
hermes-feishu-card integrity migrate-safe \
  --config CONFIG \
  --hermes-dir HERMES_DIR \
  --yes
```

只有 Git root/ancestry、owned blobs、backup、manifest、anchors 和可逆 patch 全部一致才成功。成功后 `sidecar.restart_required: true`、`gateway.restart_required: false`；先重启 sidecar。之后 runtime 通过 `hfc-runtime-v1` 发送 `runtime.hello` 和 `runtime.heartbeat`。

若 safe repair 真的重新安装了 hook，readiness 会改为 `gateway.restart_required: true`。HFC 不会自动重启 Gateway；用户在合适窗口手动重启，匹配的新 `runtime.hello` 才恢复 ready。若看到 `manual_review_required`、`control_auth_unavailable`、dirty target、branch rewind、symlink 或 source-stripped evidence，不要强制覆盖，改用 `doctor --explain` 审核。

## service.manager

```yaml
service:
  manager: auto  # auto | systemd-user | systemd-system | detached
```

| 值 | 行为 | 权限边界 |
|---|---|---|
| `auto` | 有 user manager 时用 `systemd-user`，否则 `detached` | 不查询 system bus，不调用 `sudo` |
| `systemd-user` | 明确要求 user manager | 不可用即失败，不 fallback |
| `detached` | owned detached process | 跨平台与容器默认安全边界 |
| `systemd-system` | Linux transient system unit | 仅显式 opt-in；不写 `/etc`，不调用 `sudo` |

状态文件记录 manager、unit、token 与 PID。任何 identity 不一致、活进程归属不明或 state-dir symlink 都必须 fail-closed，不得 kill 未验证进程。

Docker Compose 是普通容器流程：setup 完成后启动 sidecar，健康后再启动 Gateway；环境固定 `HERMES_FEISHU_CARD_SERVICE_MANAGER=detached`。发布门禁实际以 `install-docker.sh` 安装并 patch fixture Hermes，随后让 sidecar、Gateway 和 probe 以 non-root 身份运行；已打补丁 Gateway 必须先送达签名 `runtime.hello` 并达到 ready，再经 hook 送达真实签名 `POST /events`。不要在容器中启动 systemd，不要增加 privileged、host PID 或 `/etc/systemd/system` mount。

## 常见排障

| 现象 | 检查 | 安全动作 |
|---|---|---|
| `chats use-native` 后当前卡仍更新 | 当前 turn 的策略已固定 | 等下一条新消息；不要中途切换 |
| 未知 profile 或配置 reload 失败 | `doctor --explain`、配置语法 | 原生消息是预期 fail-open；修复配置后重试 |
| 表格 6+ 变成字段列表 | `card.table_overflow_mode` | 这是 `compact` 的无损兼容渲染；需要旧行为才选 `truncate` |
| 卡片显示 handoff，完整答案是原生消息 | final JSON 超过 28,000 byte | 这是内容保护，不应重发或手工拆掉一半答案 |
| readiness 为 starting/degraded | `runtime.hello` / `runtime.heartbeat` age | 检查 sidecar 与 Gateway runtime 版本、transport state；不把 liveness 当 readiness |
| `sidecar.restart_required: true` | 刚运行 `integrity migrate-safe` | 重启 sidecar；此步 `gateway.restart_required: false` |
| `gateway.restart_required: true` | strict repair 已完成 | 选择无活动对话窗口手动重启 Gateway；HFC 不自动执行 |
| `systemd-user` unavailable | user manager 是否可用 | 启用 user manager 或显式选 `detached`，不要改成 sudo wrapper |
| Docker 内 systemd 错误 | manager 配置 | 使用普通容器进程与 `detached` |
